<objective>
Die Bedienelemente der Filterleiste bekommen ihre Adressen, und der Cursorpfad
bekommt seine Bindung an den Anfragezustand. Danach kann ein Chipklick auf Seite
sieben nicht mehr auf Seite sieben einer anderen Ergebnismenge landen.

Purpose: `cursorPath()` prüft heute die FORM des Pfades und nicht seine HERKUNFT.
Solange die Seite nur ein Formular hatte, reichte das, denn das Formular trägt
weder `page` noch `cursors`. Ein Chip ist dagegen ein `<a>` mit den aktuellen
Parametern und nähme den Pfad mit. Zwei Regeln greifen deshalb zusammen: die
Links werden aus einem Bauteil gebaut, das gar keinen Cursor schreiben kann, UND
der Pfad bekommt einen Fingerabdruck. Beides, nicht eines von beiden, weil die
Adresse von Hand editierbar ist.

Output: `filterUrl()`, der Fingerabdruck `fp`, die Cursor-Bindung, die
Template-Parameter für die zehn Chips, die drei Sortierlinks, den
Zurücksetzen-Link und das formatierte Änderungsdatum je Treffer.
</objective>

Der heutige Adressbau (`PageController::pageUrl()`), woertlich:

```php
	private function pageUrl(string $query, bool $titleOnly, int $page, array $cursors): string {
		$arguments = [
			'query' => $query,
			'page' => (string)$page,
			'cursors' => implode('.', $cursors),
		];
		if ($titleOnly) {
			$arguments['names'] = '1';
		}

		return $this->urlGenerator->linkToRoute('findling.page.index', $arguments);
	}
```

Der URL-Vertrag aus 13-UI-SPEC, verbindlich fuer diesen Plan:

- `fp` sind acht Hexzeichen; eine Abweichung heisst Seite 1, still.
- Jeder Chip-, Sortier- und Zuruecksetzen-Link traegt NIEMALS `page`, `cursors`
  oder `fp`. Sie entstehen aus einem eigenen Bauteil neben `pageUrl()`, das gar
  keinen Cursor schreiben kann. Zwei Bauteile statt eines Schalters, weil ein
  Schalter beim naechsten Umbau falsch gesetzt wird.
- `sort=relevance` wird NICHT in die Adresse geschrieben.
- Das Suchformular traegt die aktiven Filter als versteckte Felder und weiterhin
  kein `page`, `cursors`, `fp`; ein leerer Wert wird gar nicht gerendert.
- Genau ein Zeitraum-Chip kann aktiv sein: ein Klick auf einen anderen ersetzt
  den bisherigen, ein Klick auf den aktiven entfernt ihn. Typ-Chips sind
  mehrfach waehlbar, jeder schaltet seine Gruppe an oder aus.
- Der Zuruecksetzen-Link erscheint nur, wenn `SearchFilters::hasAny()` gilt.
- Das Datum je Treffer erscheint NUR bei `sort=newest` oder `sort=oldest`, nie
  unter `relevance`, auch nicht versteckt.

`IDateTimeFormatter::formatDate($timestamp, 'long')` nimmt Zeitzone und Sprache
aus seinen eigenen Vorgaben (dem angemeldeten Nutzer) und braucht deshalb keine
weiteren Argumente. Der Katalog traegt nur das Etikett `Modified on %s`, kein
Datumsformat.

    2. Neue private Methode `fingerprint(...)`: kanonisiert den Anfragezustand
       (Begriff, `names`, sortierte Typliste, Sortiermodus, `range`, `since`,
       `until`) zu einer Zeichenkette mit einem Trennzeichen, das in keinem der
       Werte vorkommen kann, und liefert `substr(hash('sha256', $zustand), 0, 8)`.

       **Verwechslungssperre und kein Sicherheitsmerkmal**, es gibt kein
       Geheimnis, keine Signatur und nichts zu fälschen; eine Kollision ist
       harmlos, weil der Cursor ausschließlich erlaubte Kandidaten zählt und die
       schlimmste Folge eine Seite zu viel statt Seite eins ist. Zweiter Satz:
       die Kanonisierung steht VOR dem Hashen, sonst fiele ein Nutzer beim
       Umsortieren derselben Auswahl auf Seite eins.

    3. In `index()`: `fp` aus der Adresse lesen (nur acht Hexzeichen gelten als
       Form) und gegen den selbst berechneten Fingerabdruck halten. Bei
       Abweichung gilt derselbe Weg wie bei einem Pfad, der die Formprüfung nicht
       besteht: `cursors` wird `[0]` und `page` wird `1`, still. Der bestehende
       Kommentar dort wird fortgeschrieben, nicht ersetzt.

    4. `previousUrl()` und `nextUrl()` tragen den Fingerabdruck mit, denn sie
       sind die einzigen Links, die einen Cursorpfad weitergeben dürfen. Ein
       Kommentar sagt das ausdrücklich, damit die Asymmetrie zu `filterUrl()`
       lesbar ist.
