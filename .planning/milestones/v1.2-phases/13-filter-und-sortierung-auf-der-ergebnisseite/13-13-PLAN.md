<objective>
Die Phase wird abgenommen: ein Gesamtlauf aller Gates, der Audit-Durchgang aus
der Owner-Regel, und die 17 Sichtproben des Entwurfsvertrags an einer laufenden
Instanz.

Purpose: Zwei Owner-Regeln aus `CLAUDE.md` gelten für jede Phase dieses Projekts:
nach Fertigstellung aller Merkmale wird vor der Abgabe ausgiebig geprüft und
nicht nur der glückliche Pfad, und nach jeder Phase folgt ein Security-, Bug- und
Performance-Durchgang, dessen Befunde vor dem Phasenabschluss behoben werden.
Dazu kommt, dass ein gutes Dutzend Zusagen dieser Phase (Tastaturbedienung,
Screenreader, dunkles Theme, Handybreite, Zeitzonenverhalten um Mitternacht)
nicht als Text prüfbar sind und nur an einer laufenden Seite fallen können.

Output: das Protokoll in der SUMMARY und die Freigabe des Owners.

Die sieben Entscheidungen, die an der laufenden Seite wiederzufinden sind:

| ID | Zusage |
|---|---|
| D-01 | Mehrfachauswahl der sechs Typgruppen, kombinierbar, Backend-Feld ist eine Liste |
| D-02 | Chip-Leiste ueber der Trefferliste, alle sechs immer sichtbar, serverseitige Links ohne JavaScript |
| D-03 | drei Sortierlinks als Segmentschalter, aktiver hervorgehoben, ein Klick wechselt sofort |
| D-04 | Datum je Treffer NUR unter Datums-Sortierung; nie ein Relevanzwert |
| D-05 | vier Schnellbereiche als Link-Chips, keine freien Datumsfelder; Dialog-Datumsfilter zusaetzlich uebernommen |
| D-06 | aktive Chips hervorgehoben mit x zum Einzeln-Entfernen, daneben ein Zuruecksetzen-Link, nur bei mindestens einem aktiven Filter |
| D-07 | eigener Leerzustand bei 0 Treffern unter aktivem Filter, mit Link auf dieselbe Suche ungefiltert |
