<objective>
Die Adresse der Ergebnisseite lernt fünf neue Werte lesen: `types`, `sort`,
`range`, `since` und `until`. Alle fünf sind geschlossene Werte mit stillem
Rückfall, und aus ihnen entsteht das `SearchFilters`-Objekt, das die Suche
eingrenzt.

Purpose: FILT-04 verlangt, dass Filter und Sortierung in der URL reisen. Jeder
dieser Werte ist untrusted input, und die Hausregel dieser Datei ist eindeutig:
still zurückfallen statt melden, weil eine Meldung über die Adresszeile nur von
jemandem gelesen wird, der sie selbst editiert hat. Die Kalendergrenzen der
Schnellbereiche sind dabei die eine Stelle, an der eine Zeitzone gebraucht wird:
"Heute" ist kein Epochenwert, sondern eine Aussage über einen Kalendertag, und
der beginnt in der Zeitzone des Nutzers. Wer hier die Serverzeitzone nimmt,
liefert nachts ein "Heute" ohne die Dateien der letzten Stunden.

Output: die Leser, die Kalendergrenzen, `filters()`, die zwei neuen
Konstruktorabhängigkeiten und die Testfälle.
</objective>

```php
	private function pageNumber(): int {
		$raw = $this->request->getParam('page', '');
		if (!is_string($raw) || !ctype_digit($raw)) {
			return 1;
		}

		$page = (int)$raw;

		return $page >= 1 && $page <= self::MAX_PAGE ? $page : 1;
	}
```

Der URL-Vertrag aus 13-UI-SPEC, verbindlich:

| Parameter | Form | Pruefung |
|---|---|---|
| `types` | Kommaliste aus der geschlossenen Sechser-Menge, hoechstens sechs | kleinschreiben, gegen die Liste pruefen, Unbekanntes still weglassen, Dubletten entfernen, in der Reihenfolge der Sechser-Menge kanonisieren; leere Liste = kein Typfilter |
| `sort` | `relevance`, `newest`, `oldest`; `relevance` wird NICHT in die Adresse geschrieben | alles andere gilt still als `relevance` |
| `range` | `today`, `week`, `month`, `year` | alles andere gilt still als nicht gesetzt |
| `since`, `until` | Ganzzahl, Unix-Epoche in Sekunden, `>= 0`, mit Obergrenze | Nichtzahl oder ausserhalb gilt still als nicht gesetzt |

Die vier Kalenderfenster, in der Zeitzone des Nutzers (`OCP\IDateTimeZone`,
`@since 8.0.0`, im Fenster 33 bis 35 vorhanden). Alle vier setzen nur `since`,
nie `until`:

| Name | Untergrenze |
|---|---|
| `today` | heute 00:00 |
| `week` | vor 6 Tagen 00:00 (sieben Kalendertage einschliesslich heute) |
| `month` | vor 29 Tagen 00:00 (dreissig Kalendertage einschliesslich heute) |
| `year` | 1. Januar dieses Jahres 00:00 |

Zusammenspiel von `range` und `since`/`until` (13-UI-SPEC, URL-Vertrag): beide
wirken unabhaengig und grenzen beide EIN, nie aus. Sind beide gesetzt, gilt die
engere Grenze: wirksames `since` ist das Maximum aus der Schnellbereichsgrenze
und dem rohen `since`, wirksames `until` ist das rohe `until`.

Aus Plan 13-04 und 13-05 steht bereit:

```php
final class SearchFilters { /* types, sort, since, until; TYPES; SORTS; SORT_DEFAULT; EPOCH_MAX; none(); hasAny() */ }
SearchService::run(IUser $user, string $term, bool $titleOnly, int $startCursor, SearchCaps $caps, SearchFilters $filters): SearchOutcome
```

Zwei Fallen, am Code belegt: der Klassen-Docstring dieser Datei darf weiterhin
KEIN Route-Attribut beim Namen nennen (`test_php_trust_boundary.py` zaehlt solche
Erwaehnungen), und neue Konstruktorabhaengigkeiten ziehen zwei Mocks in
`PageControllerTest::setUp()` nach.
