<objective>
Der Datumsfilter des Unified-Search-Dialogs wird deklariert und beachtet. Findling
verschwindet damit nicht mehr stumm aus dem Dialog, sobald jemand ein Datum
setzt.

Purpose: `SearchComposer::buildFilter()` wirft `UnsupportedFilter`, wenn ein
exklusiver Filter gesetzt ist, den der Provider nicht deklariert, und
`UnifiedSearchController::search()` antwortet dann mit HTTP 400 für diesen
Provider; zusätzlich liest die Oberfläche die Filterliste je Provider und fragt
ihn gar nicht erst. Für den Nutzer sieht beides gleich aus: Findling ist weg. Die
Reparatur ist eine Zeile plus ihre Wirkung.

Output: `getSupportedFilters()` mit `BUILTIN_SINCE` und `BUILTIN_UNTIL`, ein
defensiver `epochOf()`, der Aufbau des `SearchFilters`-Objekts für den
Dialogfall, und die Testfälle.
</objective>

<interfaces>
Der Ist-Zustand (`php/lib/Search/Provider.php`):

```php
	#[\Override]
	public function getSupportedFilters(): array {
		return [IFilter::BUILTIN_TERM, IFilter::BUILTIN_TITLE_ONLY];
	}

	private function titleOnly(ISearchQuery $query): bool {
		$filter = $query->getFilter(IFilter::BUILTIN_TITLE_ONLY);

		return $filter !== null && $filter->get() === true;
	}
```

Upstream, gelesen an `nextcloud/server` Branch `stable33`:

- `lib/public/Search/IFilter.php` definiert `BUILTIN_TERM`, `BUILTIN_SINCE`,
  `BUILTIN_UNTIL`, `BUILTIN_PERSON`, `BUILTIN_TITLE_ONLY`, `BUILTIN_PLACES`,
  `BUILTIN_PROVIDER`, alle `@since 28.0.0`. Das Fenster des Projekts ist 33 bis
  35, die Konstanten sind also in allen drei vorhanden.
- `lib/private/Search/Filter/DateTimeFilter.php`: der Wert eines Datumsfilters
  ist ein `\DateTimeImmutable`; `->getTimestamp()` liefert die Epoche direkt und
  damit zeitzonenfrei gegen `mtime` vergleichbar.
- `lib/private/Search/SearchComposer.php` und
  `core/Controller/UnifiedSearchController.php`: ein nicht deklarierter
  exklusiver Filter endet in `UnsupportedFilter` und HTTP 400 fuer diesen
  Provider.

Aus Plan 13-04 und 13-05 steht bereit:

```php
final class SearchFilters { /* types, sort, since, until; none(); hasAny() */ }
SearchService::run(IUser $user, string $term, bool $titleOnly, int $startCursor, SearchCaps $caps, SearchFilters $filters): SearchOutcome
```

`getCustomFilters()` bleibt leer, mit dem bestehenden Docstring-Grund: ein Name
ohne `FilterDefinition` macht die ganze Providerliste kaputt. Dateityp und
Sortierung gibt es in v1.2 ausschliesslich auf der eigenen Seite (13-UI-SPEC,
Abschnitt "Grenzen zu anderen Vertraegen", Zeile Dialog-Filter).

    In `php/lib/Search/Provider.php`:

    1. `getSupportedFilters()` gibt zusätzlich `IFilter::BUILTIN_SINCE` und
       `IFilter::BUILTIN_UNTIL` zurück. Der bestehende Docstring erklärt bereits
       die Wirkung eines fehlenden Eintrags und wird um den Datumsfall
       fortgeschrieben: bis zu dieser Phase verschwand Findling bei gesetztem
       Datum aus dem Dialog, entweder weil die Oberfläche ihn nicht mehr fragte
       oder weil seine Gruppe mit HTTP 400 endete, und beides sah für den Nutzer
       gleich aus.

    2. Neue private Methode `epochOf(ISearchQuery $query, string $name): ?int`,
       wörtlich nach der Form von `titleOnly()`: den Filter holen, bei `null` mit
       `null` antworten, den Wert nur dann als Epoche lesen, wenn er ein
       `\DateTimeImmutable` ist, und in jedem anderen Fall `null` liefern. Der
       Docstring sagt, warum: der Wert eines Datumsfilters ist drüben ein
       `DateTimeImmutable`, alles andere wäre ein Defekt dort, und ein Defekt
       drüben gilt hier als "nicht gesetzt" statt als Ausnahme. Zweiter Satz:
       `getTimestamp()` ist zeitzonenfrei und damit direkt gegen `mtime`
       vergleichbar, weshalb der Dialogpfad im Gegensatz zu den Schnellbereichen
       der eigenen Seite keine Zeitzone braucht.

    3. `search()` baut aus den beiden Werten ein `SearchFilters` und übergibt es
       an `SearchService::run` statt `SearchFilters::none()`: keine Typgruppen,
       `sort` auf der Vorgabe, `since` und `until` aus dem Dialog. Kommentar: der
       Dialog kennt weder Typgruppen noch Sortierung, und beide Lücken sind
       Absicht und keine offene Baustelle.

    4. Die Werte werden vor der Übergabe auf `0` bis `SearchFilters::EPOCH_MAX`
       geklemmt, damit ein absurder Wert von drüben nicht als Bereichsabfrage
       über einen absurden Raum endet.

    5. `getCustomFilters()` bleibt leer und unverändert. Ein Satz im Docstring
       hält fest, dass Typ und Sortierung in v1.2 ausschließlich auf der eigenen
       Seite leben, weil ein Name ohne `FilterDefinition` die ganze
       Providerliste kaputt macht.

    6. Die `resourceUrl` in die Ergebnisseite bleibt in diesem Plan unverändert:
       der Dialog übergibt seinen Datumsfilter nicht an die Adresse der eigenen
       Seite. Ein Satz dazu im Kommentar, damit die Auslassung als Entscheidung
       lesbar ist und nicht als Vergessenes.

    Keine neue Route, kein Route-Attribut in der Prosa dieser Datei.
