<objective>
Die dritte langlebige Aufgabe in der Lifespan: sie zaehlt den Leerlauf, gibt
beide Halter frei und waermt nach, und sie endet mit dem Container wie ihre zwei
Geschwister.

Purpose: Erfolgskriterium 3 der Phase und MEM-02. Ohne einen Takt bleibt jede
Freigabe eine Methode, die niemand ruft.

Output: `_release_when_idle`, ein `RELEASE_TICK_SECONDS`, ein viertes
Stopp-Event und drei Zeilen im `finally`.

**Warum nicht im Leerlaufzweig des Pollers.** Ein stummgeschalteter Poller
wartet in `run()` auf `self._armed` und betritt `run_once` nie wieder
(`poller.py:543-545`). Genau dieser Container, der nicht indexiert und nur
gelegentlich durchsucht wird, ist der Fall, fuer den die Entladung gebaut wird.
</objective>

Drei Ergaenzungen in `backend/src/findling/main.py`.

1. **Konstante** `RELEASE_TICK_SECONDS: Final = 30.0` auf Modulebene, mit
   Begruendungsabsatz: der Takt ist die Aufloesung der Leerlauf-Uhr, nicht die
   Frist. Bei einer Untergrenze der TTL von 60 s liegt die Ungenauigkeit einer
   Entladung damit unter der Haelfte der kuerzesten erlaubten Frist, und ein
   Takt, der nichts zu tun hat, kostet eine Uhrenlesung.

2. **`_release_when_idle(stop_event: asyncio.Event) -> None`**, direkt hinter
   `_guarded_reconcile`, nach dessen Bauform. Rumpf:

   ```
   while not stop_event.is_set():
       await _pause(RELEASE_TICK_SECONDS, stop_event)
       try:
           ttl = settings().embed_idle_release_seconds
           if warm_wanted():
               await asyncio.to_thread(warm)
               continue
           poller = active_poller()
           if poller is not None and poller.busy:
               continue
           if await asyncio.to_thread(release_if_idle, ttl):
               if poller is not None:
                   await asyncio.to_thread(poller.release_cutter)
       except asyncio.CancelledError:
           raise
       except Exception as error:
           LOGGER.error("the release task ended in an unexpected %s; search and indexing continue", type(error).__name__)
   ```

   Die drei Punkte, die als Kommentar danebenstehen muessen:
   - **`asyncio.to_thread` fuer alle drei Aufrufe.** `gc.collect()` und
     `malloc_trim` blockieren, und ein blockierter Loop ist ein Container, der
     aufhoert, `/heartbeat` zu beantworten, waehrend sein eigenes Protokoll
     kerngesund aussieht. Das ist die ausgeschriebene Hausregel im Kopf von
     `worker/poller.py` und in `run_once`.
   - **Waermen und Entladen nie im selben Takt** (`continue`). Sonst wuerde der
     Takt, der gerade 118 MB bezahlt hat, sie im selben Durchgang wieder
     wegwerfen.
   - **`release_cutter` erst NACH einer erfolgreichen Freigabe der Suchseite.**
     Beide Halter fallen zusammen (MEM-02), und die Reihenfolge ist nicht
     beliebig: `release_if_idle` traegt die Uhr und die Identitaetspruefung,
     `release_cutter` traegt keine eigene Frist. Ein `release_cutter` ohne
     vorangegangene Freigabe wuerde den Cutter nach jeder Ruhephase wegwerfen,
     auch wenn die Suchseite gerade eingebettet hat.
   - Der `except asyncio.CancelledError: raise`-Zweig steht vor dem allgemeinen,
     genau wie in `_guarded_reconcile`: ein abgebrochener Task darf nicht als
     unerwarteter Fehler im Protokoll landen.

   `_pause` wird aus `findling.worker.poller` importiert. Es ist privat; der
   Import bekommt einen Kommentar, der sagt, warum er trotzdem richtig ist (eine
   zweite Kopie derselben drei Zeilen waere eine zweite Wahrheit ueber das
   Stoppverhalten) und dass die Alternative, `_pause` oeffentlich zu machen, eine
   Aenderung an einem Modul waere, das dieser Plan sonst nicht anfasst.

3. **In der Lifespan**, hinter dem Reconcile-Block: ein viertes Stopp-Event und
   die bedingte Erzeugung.

   ```
   stop_release = asyncio.Event()
   releasing: asyncio.Task[None] | None = None
   if settings().embed_idle_release_seconds > 0:
       releasing = asyncio.create_task(_release_when_idle(stop_release))
       LOGGER.info("findling releases the embedding engine after an idle span")
   ```

   Ohne `else`-Zweig mit Logzeile: der Werksstand ist aus, und eine Zeile bei
   jedem Start ueber eine Funktion, die niemand eingeschaltet hat, ist Rauschen.
   Der Kommentar sagt das, damit niemand die Zeile spaeter "zur Symmetrie" mit
   dem Reconcile-Block ergaenzt.

   Im `finally`: `stop_release.set()` neben den beiden anderen, und der
   Aufraeumblock nach dem Muster von `repairing`, mit einem eigenen
   `RELEASE_STOP_SECONDS` (Wert 5.0, Begruendung: ein Takt haelt hoechstens einen
   `to_thread`-Aufruf, und der laengste davon ist ein Warmlauf).
