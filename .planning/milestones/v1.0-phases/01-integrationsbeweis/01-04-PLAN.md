<objective>
Der Container bekommt sein Skelett: AppAPI-Handshake, ein Suchendpunkt und ein Treffer, der beweisbar im Container entstanden ist.

Purpose: Das ist die Container-Hälfte des Integrationsbeweises. Der Treffer muss unfälschbar sein, sonst beweist das Video nichts. Deshalb trägt er den Hostnamen des Containers, einen Zeitstempel und die aus dem signierten Header gelesene Nutzer-ID.
Output: Lauffähige ExApp, die per occ registrierbar ist und auf POST /search eine Antwort im eingefrorenen Klartext-Protokoll liefert.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| AppAPI-Proxy zum Container | Alles, was den Proxy erreicht, kann beliebige Bodies senden |
| Container zu Nextcloud-Daten | Der Container darf nur das sehen, was die signierte Identitaet erlaubt |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-11 | Elevation of Privilege | POST /search, Nutzeridentitaet | mitigate | Nutzer-ID ausschliesslich aus Depends(anc_app) und dem signierten Header; Body-Feld userId wird per extra="forbid" plus 400-Handler abgelehnt; eigener Testfall |
| T-01-12 | Spoofing | Auth-Header-Pruefung | mitigate | Keine eigene Header-Auswertung, ausschliesslich AppAPIAuthMiddleware aus nc_py_api; eigenes Parsen waere eine Authentifizierungsluecke |
| T-01-13 | Elevation of Privilege | Impersonation ueber set_user | mitigate | `set_user` steht auf der Verbotsliste von Gate A und wird in nc/client.py nicht re-exportiert |
| T-01-14 | Input Validation (V5) | SearchRequest | mitigate | Pydantic mit min_length fuer query, ge/le fuer limit, extra="forbid" fuer den gesamten Body |
| T-01-15 | Information Disclosure | Logging | mitigate | Kein Suchbegriff und kein Snippet-Inhalt im Log; nur Statusmeldungen und Nutzer-ID auf debug |
</threat_model>
