Der zweite Beweis dieser Phase: der Container liest echte Dateiinhalte rechtegeprüft, und ein Lauf über den Referenzkorpus belegt per Prüfsumme, dass dabei keine einzige Nutzerdatei angefasst wurde.

Output: Gekapselter Binärabruf über das Content-Gateway, ein Referenzkorpus mit bewusst defekten Dateien und ein CI-Gate, das Inhalte, Änderungszeitpunkte und Dateizahl vergleicht.

<interfaces>
Content-Gateway von aussen (RESEARCH.md Code-Beispiel 5):
  GET /ocs/v2.php/apps/findling/files/{fileId}?userId=<uid>
  Antwort: StreamResponse mit den Rohbytes, 404 wenn die Datei fuer diesen Nutzer nicht
  aufloesbar ist, 422 wenn sie nicht geoeffnet werden kann, 500 bei unbekanntem Fehler.

Warum NICHT nc.ocs() (RESEARCH.md Pitfall 4):
  AsyncNcSessionBasic.ocs() macht bedingungslos loads(response.text). Ein Bytestrom sprengt das
  mit einer JSON-Exception. response_type="json" ueberspringt nur das OCS-Envelope, nicht das
  JSON-Parsen. Der Abruf laeuft ueber nc._session.download2stream(url_path, fp, dav=False),
  das intern adapter.get(..., stream=True) nutzt und in Bloecken schreibt.
  Das ist eine private API (Assumptions Log A4): sie gehoert gekapselt in nc/client.py, damit ein
  nc_py_api-Update genau eine Datei trifft.

Gate B, Ablauf (RESEARCH.md "Nur-Lesen-Invariante: der konkrete Gate-Bauplan"):
  cp -r testdata/corpus data/admin/files/corpus
  ./occ files:scan --all
  find data/admin/files/corpus -type f | sort > filelist.txt      # Liste EINMAL erzeugen
  xargs -a filelist.txt sha256sum > before.txt
  xargs -a filelist.txt stat -c '%n %Y %s' > before-meta.txt
  uv run python -m findling.tools.read_corpus
  xargs -a filelist.txt sha256sum > after.txt
  xargs -a filelist.txt stat -c '%n %Y %s' > after-meta.txt
  diff before.txt after.txt && diff before-meta.txt after-meta.txt
  Zusaetzlich pruefen, dass die Dateizahl gleich geblieben ist; ein diff ueber Pruefsummen allein
  faengt geloeschte Dateien nur, wenn die Liste vorher fix ist.

Referenzkorpus (CONTEXT.md "Specific Ideas" plus RESEARCH-Empfehlung):
  PDF mit Textlayer, PDF ohne Textlayer, DOCX, TXT, Bild,
  plus zwei bewusst defekte Dateien: eine Nullbyte-PDF und eine passwortgeschuetzte PDF.
  Der Fehlerpfad ist der Pfad, auf dem der Vorgaenger Nutzerdaten geloescht hat.
