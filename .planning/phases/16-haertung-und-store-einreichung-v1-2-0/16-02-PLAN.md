**Die Bauform**, nach Muster 1 des Recherchedokuments:

1. Konstanten oben, je mit Begruendung. `DOCS_DIR` ist `REPO_ROOT / "docs"`.
2. `scan_secrets(name, text) -> list[str]`, liefert Befunde und wirft nie.
3. **Anti-Leerlauf-Klausel:** ein eigener Fall haelt fest, dass das Gate
   mindestens `DOCS_FILES_FLOOR` Dateien sieht. Die Zahl wird beim Bau einmal
   gezaehlt und mit dem Zaehldatum daneben eingetragen; ein Gate ueber ein
   verschobenes Verzeichnis waere sonst gruen ohne Aussage.
4. Ein Fall je Familie ueber alle Dateien, der die Befundliste gegen die
   Ausnahmeliste haelt.
5. **Selbsttests je Familie:** ein sauberes gestagtes Muster liefert `[]`, ein
   mutiertes liefert genau einen Befund. Ohne diesen Teil kann ein Gate, dessen
   Rumpf geloescht wurde, null Befunde ueber null Dateien melden und gesund
   aussehen.

Binaerdateien (Bilder) werden an ihrer Endung uebersprungen, und dieser Sprung
steht als eigene Konstante mit Grund da, nicht als stiller `try/except`.

**Die Ausnahmeliste `AUSNAHMEN`.** Eine Abbildung von (Pfad, Familie) auf einen
Grund als Text. Regeln: je Eintrag genau ein Grund in einem Satz, kein
Sammelsatz, und kein Eintrag ohne Grund (ein Fall haelt fest, dass jeder Grund
laenger als 20 Zeichen ist). In diesem Plan wird die Liste so gefuellt, dass das
Gate gruen ist: jeder heutige Fund bekommt seinen Eintrag, darunter die 58
Altfunde aus 18 Dateien. Die Liste nennt die Fundstellen ueber Pfad und Familie
und **zitiert keinen Wert**; ein Gate, das die Werte traegt, waere die
neunzehnte Datei, die sie traegt.

Ueber der Liste steht, dass sie im Folgeplan 16-05 schrumpft und was dann
stehen bleibt (Rohdaten gefahrener Anfahrten, weil eine nachtraeglich redigierte
Rohdatei kein Beleg mehr ist, und die eine oeffentliche Abbildkennung I-01).
