<objective>
Das Image bringt die deutsche Wortliste mit, der Admin bekommt seine Stellschrauben als Umgebungsvariablen, und die unangenehme Wahrheit über den gespeicherten Dokumenttext steht in der Store-Beschreibung.

Purpose: Zero-Config heißt, dass beim ersten Start nichts heruntergeladen wird. Eine Firewall, ein Proxy oder eine Offline-Installation dürfen die deutsche Sprachqualität nicht kosten. Und weil `body_de` gespeichert wird, liegt der vollständige extrahierte Text aller indexierten Dokumente im App-Volume. Für Snippets ist das unvermeidbar, aber ein Admin muss es wissen, insbesondere weil AIO-Sicherungen dieses Volume erfassen können. Eine solche Aussage gehört in den Store-Text, nicht in eine stille Annahme.
Output: Wortlistenpaket im Laufzeitimage samt Lizenztext, aktualisierte ExApp-Metadaten und eine Lizenzdatei für alle Fremdartefakte.
</objective>

<interfaces>
Wortliste im Image (RESEARCH "Standard Stack", Dockerfile-Ausschnitt, und "Frage 1",
Abschnitt "Die Wortliste: Herkunft, Lizenz, Rezept"):

  RUN apt-get update \
   && apt-get install -y --no-install-recommends wngerman \
   && rm -rf /var/lib/apt/lists/*
  # /usr/share/dict/ngerman, 356010 Zeilen, 4725887 Byte, GPL-2+

  Das Paket bleibt im LAUFZEITIMAGE. Es wird nicht in einer Build-Stage destilliert
  und wieder entfernt: die Aufbereitung ist ein Startschritt (RESEARCH Pattern 4),
  der die Liste einmal auf das Laengenfenster reduziert und als
  $APP_PERSISTENT_STORAGE/dict/de.txt mit SHA-256 ablegt. Existiert die Datei mit
  passendem Hash, wird sie direkt geladen. Damit haengt die Tokenisierung an einem
  Artefakt im Volume, dessen Hash in der Metatabelle steht, und nicht an einer
  Bauentscheidung.
  Architecture: all, also identisch auf amd64 und arm64. Version gepinnt, nicht
  latest gezogen.

Lizenzpflicht: GPL-2+ (Copyright Bjoern Jacke, Quellpaket igerman98, Maintainer
Roland Rosenfeld), vertraeglich mit AGPL-3.0 ueber GPLv3. Lizenztext und Herkunft
gehoeren ins Image, nicht nur ins Repo, und das Aufbereitungsskript bleibt im
Repo, weil abgeleitete Daten weitergegeben werden. Debian legt den Text unter
/usr/share/doc/wngerman/copyright ab; slim-Images koennen Dokumentation
ausschliessen, deshalb wird die Datei ausdruecklich an einen stabilen Ort kopiert.

Store-Metadaten (Phase-1-Befund aus 01-07): der Store validiert info.xml nicht wie
sie dasteht, sondern nach pre-info.xslt; unbekannte Elemente werden still
verworfen. Der routes-Block wird deshalb nicht validiert, sondern von AppAPI aus
dem Release-Archiv gelesen. Die Datei muss unveraendert im Tarball liegen.

Neue Routen: snippets (POST, USER), status (GET, ADMIN). search bleibt wie es ist.
Nichts ist PUBLIC. ADMIN ist strenger als die USER-Grundlinie der Sicherheitsliste
und passt zur Statusanzeige, die Phase 4 baut.

Neue Umgebungsvariablen, Namen exakt wie in backend/src/findling/config.py:
  FINDLING_LANGUAGES      Vorgabe de,en
  FINDLING_COMPOUND_DICT  Vorgabe full, Alternative nouns (gemessene Sparvariante,
                          86.345 statt 276.496 Eintraege, 12 statt 14 von 16
                          Komposita)
  FINDLING_MAX_FILE_BYTES Vorgabe 52428800
  FINDLING_LOG_LEVEL      bleibt

Aenderungen an FINDLING_LANGUAGES oder FINDLING_COMPOUND_DICT aendern die
Tokenisierung und erzwingen einen Reindex; das gehoert in die Beschreibung der
Variablen, weil es die haeufigste Ursache fuer "Treffer sind weg" nach einem
Eingriff ist.

Versionskopplung: beide Haelften fuehren dieselbe Version. php/appinfo/info.xml
geht in Plan 02-04 auf 0.2.0, diese Datei zieht mit.

Datenschutzaussage (RESEARCH "Security Domain", letzter Absatz): mit stored=True
auf body_de liegt der vollstaendige extrahierte Text aller indexierten Dokumente
im App-Volume, gemessen 0,374 x der Textgroesse. Fuer Snippets unvermeidbar, aber
ausdruecklich zu nennen, auch weil AIO-Sicherungen das Volume erfassen koennen.
