Zwei Teile, beide in einem Zug gegen denselben Baum.

**Teil A, der Gesamtlauf.** Die vollstaendige Kette, so wie `python.yml` sie
faehrt, in einem Durchgang, und das Ergebnis je Stufe ins Protokoll:

1. `cd backend && uv run ruff check .`
2. `uv run ruff format --check .`
3. `uv run pyright`
4. `uv run vulture src tests --min-confidence 80`
5. `uv run pytest -q` (die **VOLLE** Suite, nicht `tests/unit`; die Lehre vom
   17.09. ist, dass ein prozessweites Leck nur in der vollen Suite rot war)
6. `uv run ruff check --config pyproject.toml ../scripts` und
   `uv run ruff format --config pyproject.toml --check ../scripts`

Dazu die Stufen, die hier nur teilweise fahrbar sind, je mit ihrem Ersatznachweis
im Protokoll: PHP-Lint ueber das Docker-Image `php:8.2-cli` fuer die drei in
14-09 geaenderten Dateien, PHPUnit bleibt CI-Sache (die Suite braucht eine
Auscheckung von nextcloud/server), und die vier Text-Gates, die den PHP-Quelltext
lesen, laufen lokal einzeln nach (`test_php_acl_boundary.py`,
`test_php_trust_boundary.py`, `test_admin_ui_contract.py`,
`test_search_fields_lockstep.py`).

**Kein neuer Skip, keine gesenkte Schwelle, kein gelockertes Gate.** Faellt eine
Stufe, ist das ein Befund und wird behoben; die Zahl der Skips und ihre
Begruendungen werden mit dem Stand aus 13-13 verglichen (15 vorbestehende
Umgebungs-Skips) und jede Abweichung wird benannt.

**Teil B, der Audit-Durchgang.** Schreibe
`docs/audits/2026-09-phase-14/README.md` mit vier Abschnitten:

1. **Gate-Protokoll.** Tabelle Stufe zu Ausgang, mit der Testzahl und dem
   Commit, gegen den gelaufen wurde.
2. **Security, ASVS V5, V7, V12.** Je eine Feststellung mit Beleg:
   - V5: die neue Umgebungsvariable geht durch einen bereichsgeprueften Leser,
     faellt bei Unsinn auf den Default zurueck und stoppt den Container nie
     (T-02-74).
   - V7: die Logzeilen der Entladung tragen keinen Suchtext, keinen Dateinamen
     und keine Trefferzahl; die Freigabe warnt nur mit dem Typnamen (T-02-14).
     Nachweis per `grep` ueber die neuen Logzeilen.
   - V12: `ctypes.CDLL` laedt eine Systembibliothek per festem Namen, nie aus
     einem Pfad, der aus Konfiguration kommt.
   - V4 mit Vorbehalt: die lexikalische Degradation liefert keine Kandidaten an
     den Vorfiltern vorbei. Nachweis durch einen Paritaetsfall, der eine Suche
     unter `may_load=False` gegen den ACL-Vorfilter und den finalen PHP-Recheck
     stellt. Fehlt ein solcher Fall, wird er hier **angelegt**, nicht nur
     protokolliert (die Lehre aus 13-13: ein Audit-Pfad ohne Gate bekommt ein
     Gate).
   - Die fuenf Bedrohungsmuster aus 14-RESEARCH.md 17, je mit der Gegenmassnahme
     und der Stelle, an der sie steht.
3. **Bug-Durchgang.** Die Pfade, die kein Gate abdeckt, einzeln durchgesehen und
   je entschieden: Entladung waehrend eines Indexlaufs, Entladung bei einem
   Container ohne Modell, Entladung bei abgeschalteter Semantik, Entladung
   waehrend eines laufenden Batches, libc ohne `malloc_trim`, halb aktualisiertes
   App-Paar (Container kennt `unloaded`, PHP nicht). Jeder Pfad endet mit
   "durch Testfall gedeckt", "neu gedeckt" oder "erklaert und hingenommen".
4. **Performance-Durchgang.** Am Code und an den Zahlen: der Takt kostet je
   Durchgang eine Uhrenlesung; `gc.collect` und `malloc_trim` laufen nie auf dem
   Event Loop; die Nachwaerm-Aufgabe verzoegert keine Antwort; die Zahl aus dem
   Vorprueflauf steht im Bericht und nicht im Container-Log. Dazu **Annahme A9
   gegenprueft**: `vulture` und `pyright` haben keine weitere Stelle des sechsten
   Worts aufgedeckt, oder sie haben, und dann steht sie hier.
